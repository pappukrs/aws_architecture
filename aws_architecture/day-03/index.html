Public Subnet with Internet Access

Yesterday's VPC was sealed off. Today you open one door: an Internet Gateway, a route that points to it, and a public IP on the web server. Those three things are what turn a subnet into a public subnet.

The diagram

Full picture: traffic from the internet enters through the Internet Gateway attached to the VPC. The public subnet's route table sends everything that is not local (0.0.0.0/0) to that gateway, and the web server has a public IP. The private subnet has none of these, so it stays unreachable.

Concepts

Internet Gateway (IGW)

The door between your VPC and the internet. You create it, then attach it to the VPC.

  • One IGW per VPC. Draw it on the VPC border, because it belongs to the VPC, not to a subnet.
  • AWS runs it for you: it scales by itself and has no single point of failure.
  • The gateway is free; you pay for the data that leaves through it.

Route table

A list of rules: “traffic for this destination goes to that target”. Every subnet is associated with exactly one route table.

  • Every table has the local route for the VPC range. You cannot delete it.
  • 0.0.0.0/0 means “everything else”, also called the default route.
  • The most specific matching route wins: /16 beats /0.
  • A subnet with no explicit association uses the VPC's main route table.

Public IP and Elastic IP

The IGW only forwards traffic for instances that have a public IPv4 address.

  • Auto-assigned public IP — given at launch, changes when you stop and start the instance.
  • Elastic IP — a fixed public address you own until you release it.
  • The instance itself only knows its private IP. The IGW translates between the two (1:1 NAT).
  • AWS charges for every public IPv4 address, in use or not.

What “public subnet” really means

There is no “public” checkbox on a subnet. A subnet is public when its route table has a route to an Internet Gateway.

  • Same VPC, same kind of subnet; only the route table differs.
  • Keep the main route table private, and make a separate one for public subnets. Then a new subnet is private by default.

Four things needed for internet access

If an instance cannot be reached from the internet, check these in order. Miss any one and it fails.

  1. An Internet Gateway is attached to the VPC.
  2. The subnet's route table has 0.0.0.0/0 → igw.
  3. The instance has a public IP or Elastic IP.
  4. Security group and network ACL allow the traffic (Day 5).

Check yourself

What makes a subnet “public”?

Its route table has a route to an Internet Gateway, normally 0.0.0.0/0 → igw. Nothing else about the subnet is different.

An instance is in a public subnet but has no public IP. Can the internet reach it?

No. The route exists, but the IGW has no public address to map to the instance. It also cannot go out to the internet.

A packet goes from the web server to 10.0.2.10. The route table has 10.0.0.0/16 → local and 0.0.0.0/0 → igw. Which route is used?

The local route. Both match, but /16 is more specific than /0, and the most specific route wins. The packet never leaves the VPC.

You run ip addr on the web server. Do you see 13.233.10.25?

No, only 10.0.1.10. The public IP lives at the Internet Gateway, which translates it to the private IP.

You stop and start the web server. What happens to its public IP?

An auto-assigned public IP is released and a new one is given. To keep the same address, use an Elastic IP.

How many Internet Gateways can one VPC have?

One. And one IGW can be attached to only one VPC at a time.

Why not just add the IGW route to the main route table?

Because every subnet without its own association uses the main table, so any new subnet would silently become public. Keeping the main table private is the safe default.

The database server needs to download security updates. Can it today?

No. It has no route to the internet. Giving it one without exposing it is the job of the NAT Gateway on Day 4.
