Serverless API

Week 2 needed a VPC, six subnets, a load balancer and servers that run all night. Today's API has none of that. API Gateway receives the request, a Lambda function runs your code for a few milliseconds, and DynamoDB stores the data. Nothing runs, and nothing is billed, when nobody calls.

The diagram

Full picture: (1) the client sends an HTTPS request to API Gateway. (2) API Gateway invokes the Lambda function, passing the request as an event. (3) The function reads or writes items in the DynamoDB table, which its execution role permits. The response returns the same way. None of this is inside a VPC.

Concepts

API Gateway

The front door for an API. It gives you a public HTTPS endpoint and sends each route to a backend.

  • Plays the part the load balancer played in Week 2, with no subnets to place it in.
  • Checks who is calling (IAM, Cognito or a token) before your code runs.
  • Throttles: a limit on requests per second protects the backend.
  • Two main kinds: HTTP API, simpler and cheaper, and REST API, with extras such as API keys and usage plans.

Lambda

You upload a function; AWS runs it when an event arrives. You never see a server.

  • Each request runs in its own environment. A hundred at once means a hundred environments, created for you.
  • Cold start: the extra delay when a new environment must be created.
  • Billed per request and per millisecond of run time. Idle costs nothing.
  • Limits: 15 minutes per invocation, and no state kept between invocations.

DynamoDB

A managed key-value database. No instance to size, no standby to configure.

  • A table holds items; each item is found by its partition key.
  • Data is stored across three AZs automatically.
  • On-demand capacity: pay per read and write, scaling with the traffic.
  • Calls are plain HTTPS requests, so thousands of Lambda environments cause no connection-limit problem, unlike a relational database.

IAM replaces the security group

With no network of your own, there are no security groups. Access is decided by permissions.

  • The function's execution role lists exactly what it may call.
  • Least privilege: this role can write to one table and nothing else.
  • API Gateway is allowed to invoke this function by a permission on the function itself.
  • On a serverless diagram, draw the role beside the function.

Where is the VPC?

There is none. API Gateway, Lambda and DynamoDB are regional services that AWS runs on its own network. You draw them inside the Region box and stop there: no VPC, no AZ boxes, no subnets.

A function can be attached to your VPC when it must reach something that lives there, such as an RDS database or ElastiCache. It then gets network interfaces in your private subnets and a security group, and needs a NAT Gateway or VPC endpoints to reach the internet and other AWS services. Do this only when you have to.

Check yourself

Which parts of this architecture live inside a VPC?

None. All three are regional services outside your network. A Lambda function is attached to a VPC only when it needs to reach resources there, such as RDS.

What stops the function from deleting a different table?

Its execution role. The role allows only PutItem and Query on the Notes table, so any other call is denied by IAM. There is no security group involved.

What is a cold start, and when does it happen?

The extra time to create a new execution environment and load your code. It happens on the first request after idle, and whenever concurrent requests exceed the warm environments. Smaller packages and lighter runtimes shorten it; provisioned concurrency keeps environments warm for a price.

Five thousand requests arrive in the same second. What happens?

Lambda creates environments up to the account's concurrency limit, 1,000 per Region by default. Requests beyond that are throttled and the client gets an error to retry. Raise the limit, or set API Gateway throttling so the excess is rejected cleanly.

The function saves a counter in a global variable. Is that safe?

No. Each environment has its own copy, and environments appear and disappear. State must live outside the function, in DynamoDB or S3.

A report takes 40 minutes to generate. Can a Lambda function behind this API do it?

No. A function stops at 15 minutes, and API Gateway stops waiting after about 30 seconds. Start the work asynchronously and run it in a container (Day 18) or split it into steps.

Is this API highly available? What did you do to make it so?

Yes, and you did nothing. Each service runs across several AZs in the Region by design. It is still a single-Region architecture.

When would the EC2 design be the cheaper choice?

With steady, heavy traffic around the clock. Paying per request then costs more than servers that are busy all the time. Serverless wins when traffic is low, spiky or unpredictable.
