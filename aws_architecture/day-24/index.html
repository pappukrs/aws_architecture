Day 24 of 30 · Week 4 — Enterprise Architecture

Private Access to AWS Services

S3, DynamoDB and SQS are not inside your VPC. Until now, a server in a private subnet reached them the long way: out through the NAT Gateway and across public addresses. VPC endpoints give it a private door instead, so the traffic never leaves the AWS network and the NAT Gateway bill shrinks. There are two kinds, and they work quite differently.

The diagram

Full picture: four ways out of a private subnet. The grey dashed path is the old way, through the NAT Gateway to a public address. A gateway endpoint sits on the VPC border and is chosen by route table entries; it serves S3 and DynamoDB. An interface endpoint is a network interface with a private IP inside your subnet; it serves most other AWS services, and through PrivateLink it can also reach a service in someone else's VPC.

Concepts

The problem

AWS services are reached at public addresses. A private instance has no public IP, so it needs a NAT Gateway just to talk to S3.

  • Cost: the NAT Gateway charges for every GB, and S3 traffic is often the bulk of it.
  • Dependency: no NAT Gateway, no access to AWS APIs.
  • Policy: many organisations do not want private workloads to have any path to the internet.

Gateway endpoint

A target you put in a route table. Traffic for the service is sent to it instead of to the NAT Gateway.

  • Only two services: S3 and DynamoDB.
  • Free. No hourly charge, no per-GB charge.
  • Not a network interface: no IP address, no security group.
  • Works only for traffic that starts inside the VPC. Not reachable from on-premises or a peered VPC.
  • Draw it on the VPC border.

Interface endpoint

A network interface placed in your subnet, with a private IP, that leads to one service.

  • Available for most AWS services: SQS, ECR, Secrets Manager, CloudWatch and well over a hundred more.
  • Has a security group; it must allow 443 from your instances.
  • Private DNS makes the service's normal name resolve to the private IP, so code does not change.
  • Charged per hour per AZ and per GB. Put one in each AZ you use.
  • Reachable from on-premises over VPN or Direct Connect.

PrivateLink

The technology behind interface endpoints, and something you can use for your own services.

  • The provider puts a service behind a Network Load Balancer and publishes it as an endpoint service.
  • The consumer creates an interface endpoint to it in their own VPC.
  • Only that one service is exposed, in one direction. The two networks are not joined.
  • Overlapping CIDRs are not a problem, unlike peering.

S3 has both kinds. Use the free gateway endpoint from inside the VPC, and an S3 interface endpoint only when the traffic comes from on-premises.

Locking it down

  • Endpoint policy: attached to the endpoint, it limits what can be done through it, for example only these two buckets.
  • Bucket policy: on the S3 side, deny every request that does not arrive through your endpoint, using the condition aws:sourceVpce. The bucket then cannot be read from anywhere outside your VPC, even with valid credentials.
  • No NAT at all: with endpoints for every service a workload needs, a private subnet can have no route to the internet. Day 18's Fargate tasks need four: ECR API, ECR Docker, CloudWatch Logs (all interface) and S3 (gateway).

Check yourself

Which endpoint type uses a route table entry?

The gateway endpoint. You add it to a route table, and traffic for S3 or DynamoDB follows that route. An interface endpoint uses no route; it is reached through DNS resolving to a private IP in your subnet.

Which services have gateway endpoints?

Only S3 and DynamoDB. Everything else uses interface endpoints.

A private subnet has no NAT Gateway. The application must read a secret from Secrets Manager. What do you add?

An interface endpoint for Secrets Manager in that subnet, with private DNS on and a security group that allows 443 from the application.

You created the interface endpoint, but calls to the service still time out. What do you check?

The endpoint's security group must allow inbound 443 from your instances. Then check that private DNS is enabled, so the service's name resolves to the endpoint's private IP rather than the public address.

Both a NAT Gateway and an S3 gateway endpoint exist. Which does S3 traffic use, and why?

The gateway endpoint. Its route is for S3's specific address ranges, which is more specific than 0.0.0.0/0, and the most specific route wins. That S3 traffic stops being charged by the NAT Gateway.

A server in the data centre, connected by Direct Connect, must reach S3 privately. Will the gateway endpoint work?

No. Gateway endpoints serve only traffic that originates in the VPC. Create an S3 interface endpoint, which has a private IP that on-premises systems can route to.

How do you make a bucket readable only from inside your VPC?

A bucket policy that denies requests unless aws:sourceVpce matches your endpoint. Even someone with stolen credentials cannot read it from elsewhere.

A partner must offer you an API privately. Both of you use 10.0.0.0/16. Peering or PrivateLink?

PrivateLink. Peering cannot connect overlapping ranges and would expose whole networks to each other. PrivateLink exposes one service through an interface endpoint and does not care about the provider's addressing.
