Day 6 of 30 · Week 1 — Networking Foundations

Multi-AZ VPC

Everything so far lived in one Availability Zone, so one zone failure would take it all down. Today you build the network twice, side by side: a public and a private subnet in each of two AZs, and a NAT Gateway in each. This is the base layout of almost every production architecture.

The diagram

Full picture: one VPC and one Internet Gateway serve the whole Region. Each Availability Zone has its own public subnet, private subnet and NAT Gateway. The public subnets share one route table; each private subnet has its own, pointing to the NAT Gateway in its own zone. If either zone is lost, the other keeps working by itself.

Concepts

Why two AZs

An AZ can lose power or network. If everything is in one AZ, that is your outage too.

  • Put a copy of every tier in at least two AZs.
  • A subnet lives in one AZ, so you need one subnet per tier per AZ: 2 tiers × 2 AZs = 4 subnets.
  • Three AZs is common in production; two is the minimum.

What is shared, what is duplicated

  • Shared: the VPC and the Internet Gateway. Both are regional and already survive an AZ failure.
  • Shared: the public route table. Every public subnet has the same rule, 0.0.0.0/0 → igw.
  • Duplicated: subnets, NAT Gateways and private route tables. These are tied to one AZ.

One private route table per AZ

A route table has one target for 0.0.0.0/0. To send each private subnet to the NAT Gateway of its own zone, each needs its own table.

  • Private A → nat-a, private B → nat-b.
  • Traffic never crosses to the other AZ, so a failure there cannot affect it.
  • It also avoids the per-GB charge for data crossing between AZs.

The cost trade-off

Each NAT Gateway is billed per hour, so one per AZ doubles that part of the bill.

  • Production: one NAT Gateway per AZ.
  • Development or test: a single NAT Gateway is a common, accepted saving.
  • Say which one you chose and why. In an interview, that sentence matters more than the drawing.

Draw it yourself

  1. Draw the Region, the VPC and the Internet Gateway on the VPC's top border, in the middle.
  2. Draw two AZ boxes side by side inside the VPC.
  3. In each AZ, draw a public subnet on top and a private subnet below. Write a different CIDR on each of the four.
  4. Put a NAT Gateway in each public subnet.
  5. Draw three route tables: one public (shared), and one private per AZ pointing to that AZ's NAT Gateway.
  6. Draw the outbound arrows: private subnet → NAT Gateway in the same AZ → Internet Gateway → Internet.

Then press Hide diagram and redraw it from memory. This is tomorrow's review drawing, so time yourself: the goal is under 10 minutes.

Check yourself

What breaks if you use only one NAT Gateway?

If its AZ fails, private subnets in the other AZ are still running but lose their outbound internet access, because their default route points to a gateway that is gone. You also pay for data crossing between AZs in normal operation.

Do you need one Internet Gateway per AZ?

No. An Internet Gateway is attached to the VPC, is regional, and is already redundant across AZs. One per VPC is both the limit and enough.

Why can the two public subnets share a route table but the two private subnets cannot?

The public subnets have the same default route, to the one Internet Gateway. The private subnets need different targets, nat-a and nat-b, and a route table has only one target per destination.

Can public subnet A and public subnet B both be 10.0.1.0/24?

No. Subnets in one VPC must not overlap, whichever AZ they are in.

An application has web, app and database tiers and must run in three AZs. How many subnets?

Nine: one subnet per tier per AZ, 3 × 3.

AZ a fails. A user's browser was talking to the web server at 10.0.1.10. Is the user automatically sent to AZ b?

Not with this diagram alone. The network in AZ b is healthy, but nothing redirects users to it. That is the job of a load balancer, which you add on Day 8.

Can the app server in AZ a talk to the app server in AZ b?

Yes. They are in the same VPC, so the local route connects them across AZs. Security groups still decide whether it is allowed.

A startup wants the cheapest possible test environment across two AZs. What do you change?

Use a single NAT Gateway and point both private route tables at it. Accept that an AZ failure can cut outbound access, and note it as a deliberate choice.
