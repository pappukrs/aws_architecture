Security Layers

Route tables decide where traffic can go. Today you add what is allowed to go: a security group around every instance, a network ACL around every subnet, and a bastion host as the only way in for administrators.

Concepts

Security group (SG)

A firewall wrapped around an instance. Draw it as a box around the instance.

  • Stateful: if a request is allowed in, its reply is allowed out automatically.
  • Allow rules only. Anything not allowed is denied; you cannot write a deny rule.
  • A new security group allows no inbound traffic and all outbound traffic.
  • The source of a rule can be another security group, not just an IP range.

Network ACL (NACL)

A firewall at the edge of a subnet. Draw it on the subnet border.

  • Stateless: replies are checked like new traffic, so you need a rule in each direction.
  • Allow and deny rules, numbered. The lowest number is checked first and the first match wins.
  • The default NACL allows everything. A custom NACL denies everything until you add rules.
  • One NACL per subnet; it applies to every instance in it.

Bastion host

A small instance in the public subnet whose only job is to be the entry point for administrators. Also called a jump box.

  • Its security group allows SSH from your IP only, never from 0.0.0.0/0.
  • Private instances allow SSH only from the bastion's security group.
  • Today AWS Systems Manager Session Manager can replace it with no open port at all, but the bastion pattern is still asked about and still drawn.

Security group chaining

db-sg allows 3306 from web-sg, not from an IP range. This is the pattern to remember.

  • Only instances that carry web-sg get in, wherever they are and whatever their IP.
  • Add ten more web servers and the rule still works unchanged.
  • The bastion is in the same subnet as the web server but cannot reach the database on 3306.

Security groupNetwork ACL
ProtectsAn instanceA subnet
StateStateful: replies pass automaticallyStateless: replies need their own rule
Rule typesAllow onlyAllow and deny
EvaluationAll rules are considered togetherIn number order, first match wins
DefaultDeny all inbound, allow all outboundDefault NACL allows all

Why stateless matters: ephemeral ports

When the web server connects to the database on port 3306, the reply does not come back on 3306. It returns to a random high port on the web server, somewhere in 1024–65535. These are called ephemeral ports.

A security group remembers the connection and lets the reply through. A network ACL remembers nothing, so the private NACL needs an explicit outbound rule for 1024–65535. Forgetting that rule is the classic reason a custom NACL “breaks everything”.

Check yourself

Security group or network ACL: which one needs explicit rules for return traffic?

The network ACL. It is stateless, so the reply is judged as a separate packet. A security group is stateful and lets replies through automatically.

Can you write a deny rule in a security group?

No. Security groups have allow rules only. To block a specific address you use a network ACL deny rule.

Why does db-sg use web-sg as its source instead of 10.0.1.0/24?

The subnet range would also let in the bastion and anything else placed in the public subnet. Referencing web-sg lets in web servers only, and keeps working when instances are added or their IPs change.

A NACL has rule 100 ALLOW 22 from 0.0.0.0/0 and rule 200 DENY 22 from 198.51.100.9/32. Is that address blocked?

No. Rule 100 is checked first and already matches, so rule 200 is never reached. The deny must have a lower number than the allow.

The web server calls an external API. Do you need an inbound security group rule for the response?

No. The security group is stateful and outbound is allowed by default, so the response to a connection the server opened comes back in automatically.

An instance has two security groups attached. Which rules apply?

All of them, combined. If either group allows the traffic, it is allowed.

Why should bastion-sg allow SSH only from your own IP?

Port 22 open to 0.0.0.0/0 is found by scanning bots within minutes. Limiting the source to one address removes almost the whole attack surface.

You add a custom NACL with only inbound allow rules and the application stops working. Why?

There is no outbound rule for the ephemeral ports 1024–65535, so every reply is dropped on its way out of the subnet.
