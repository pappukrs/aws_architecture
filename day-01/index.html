AWS Global Infrastructure

Concepts

Region

A separate geographic area where AWS runs a full set of services, such as ap-south-1 (Mumbai) or us-east-1 (N. Virginia). There are 30+ Regions worldwide.

  • Regions are isolated from each other. Data never leaves a Region unless you copy it.
  • Most services are regional: you pick the Region first, then create resources.
  • Prices and available services differ per Region.

Availability Zone (AZ)

An isolated location inside a Region, named with a letter suffix: ap-south-1a, 1b, 1c. Every Region has at least three.

  • AZs are kilometres apart (within about 100 km), so a fire, flood or power cut hits only one.
  • They are linked by redundant private fiber with single-digit-millisecond latency.
  • High availability means spreading across at least two AZs. This is the most repeated idea in AWS design.

Data center

The physical building with servers. One AZ is one or more data centers, each with independent power, cooling and networking.

  • You never choose a data center; the AZ is the smallest unit you select.
  • In real diagrams you do not draw data centers. They are here today only so you know what an AZ is made of.

Edge location

A small site close to users, in far more cities than Regions (600+). It does not run your servers; it caches and routes.

  • CloudFront caches your content there, so a user in Delhi is served from Delhi.
  • Route 53 answers DNS queries from there.
  • Traffic then rides the private AWS backbone to the Region instead of the public internet.

How to choose a Region

  1. Compliance — if the law says data must stay in a country, that decides it.
  2. Latency — choose the Region closest to most of your users.
  3. Service availability — new services do not launch everywhere at once.
  4. Cost — the same instance costs different amounts in different Regions.

Draw it yourself

  1. Draw the outer AWS Cloud box.
  2. Add a dashed Region box and label it with code and city.
  3. Place three dashed AZ boxes side by side inside it, labelled a, b, c.
  4. Put two data centers in each AZ and connect the AZs with links.
  5. Add a second Region to the right and join the two with the backbone.
  6. Add edge locations along the bottom, with users below them and arrows pointing up.

Then press Hide diagram above and redraw it from memory in draw.io or Excalidraw. Aim for under 5 minutes.

Check yourself

Why is an AZ not the same as a data center?

An AZ is a logical group of one or more data centers. AWS can add buildings to an AZ without you noticing. The AZ, not the building, is the unit of isolation you design around.

Your app runs on two EC2 instances in the same AZ. Is it highly available?

No. It survives one instance failing, but not the AZ failing. Put the instances in two different AZs.

If the Mumbai Region goes down, does your S3 data automatically appear in Singapore?

No. Regions are isolated. You must turn on cross-Region replication yourself, and pay for it.

A user in Delhi loads an image served through CloudFront. Where does it come from?

From the nearest edge location if it is cached there. Only on a cache miss does the edge fetch it from the origin in the Region.

Is ap-south-1a in your account the same physical AZ as in someone else's?

Not necessarily. AWS maps the letters differently per account to spread load. The AZ ID (for example aps1-az1) is the same for everyone.

Where would you draw IAM on this diagram?

Outside the Region boxes. IAM is a global service; users and roles exist once for the whole account.
